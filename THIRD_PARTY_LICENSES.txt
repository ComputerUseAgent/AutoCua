THIRD-PARTY LICENCES: AutoCua's prebuilt Rust extensions
=========================================================

AutoCua's wheels ship two Rust extension modules prebuilt:
AutoCua/web/agent_native (the web agent) and AutoCua/android/agent_native (the
Android agent), each compiled for the wheel's target: x86_64-pc-windows-gnu
(Windows x64), aarch64-apple-darwin (macOS arm64), x86_64-unknown-linux-gnu
(Linux x86_64). Compiling them links in third-party code: the crates pinned in
AutoCua/web/Cargo.lock and AutoCua/android/Cargo.lock, the Rust standard
library (with compiler-builtins and the libm it bundles) and the runtime code
the linkers add: MinGW-w64's and GCC's on Windows, Zig's on Linux. This file
holds the licence texts and notices that code's licences ask binary copies to
carry. THIRD_PARTY_NOTICES.md describes each component; AutoCua's own MIT
licence (LICENSE) covers none of it.

Generated by AutoCua/utils/third_party_licenses.py from the two Cargo.lock
files, the cargo registry and the Rust toolchain, rustc 1.97.1 (8bab26f4f
2026-07-14): the release that rust-toolchain.toml at the repository root pins,
so every machine that builds a wheel links the standard library described here.
Do not edit it by hand: after a change to either Cargo.lock or to the pinned
toolchain, run

    python -m AutoCua.utils.third_party_licenses

and commit the result. `python -m AutoCua.utils.third_party_licenses --check`
exits 1 when this file is out of date.

Contents
  1. Independent JPEG Group
  2. Crates linked into each module
  3. Rust standard library
  4. Runtime code the linkers add (Windows x64 and Linux x86_64 wheels)
  5. Copyright lines in compiled sources
  6. Licence texts, numbered; the sections above cite them as [n]

4. RUNTIME CODE THE LINKERS ADD (WINDOWS X64 AND LINUX X86_64 WHEELS)
=====================================================================

Linking a module can copy runtime code from the linker's own toolchain into it,
beyond the crates and the standard library. The macOS arm64 wheel's modules
link Apple's system libraries dynamically; the other two wheels' carry what
follows.

Windows x64 wheel (x86_64-pc-windows-gnu, MinGW-w64 GCC)
--------------------------------------------------------
Both modules are built with Rust's GNU toolchain and linked by MinGW-w64 GCC,
which adds runtime code to them statically:

- MinGW-w64's C runtime start-up code (dllcrt2.o) and parts of its runtime
  libraries (libmingw32, libmingwex, the CRT import libraries). Their terms:
  MinGW-w64's COPYING.MinGW-w64-runtime.txt, below.
- winpthreads (libpthread.a), which rustc links into every Windows GNU module.
  Its terms: winpthreads' COPYING, below.
- GCC's runtime libraries: libgcc, its unwinder libgcc_eh and
  crtbegin.o/crtend.o. They are under GPL-3.0-or-later with the GCC Runtime
  Library Exception 3.1, which lets the combined work be conveyed under terms
  of the distributor's choice and has no notice condition, so no text is needed
  for them.

This file contains a slower but more accurate integer implementation of the
forward DCT (Discrete Cosine Transform).

A 2-D DCT can be done by 1-D DCT on each row followed by 1-D DCT
on each column.  Direct algorithms are also available, but they are
much more complex and seem not to be any faster when reduced to code.

This implementation is based on an algorithm described in
  C. Loeffler, A. Ligtenberg and G. Moschytz, "Practical Fast 1-D DCT
  Algorithms with 11 Multiplications", Proc. Int'l. Conf. on Acoustics,
  Speech, and Signal Processing 1989 (ICASSP '89), pp. 988-991.
The primary algorithm described there uses 11 multiplies and 29 adds.
We use their alternate method with 12 multiplies and 32 adds.
The advantage of this method is that no data path contains more than one
multiplication; this allows a very simple and accurate implementation in
scaled fixed-point arithmetic, with a minimal number of shifts.
